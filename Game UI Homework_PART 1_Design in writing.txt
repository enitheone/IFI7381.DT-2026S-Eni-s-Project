Element 1: Mute button
-------------------------------
What states can it be in?
- it can be in two states:
	* False - music plays
	* True - music is muted (not paused)

How does content get in, and out?
- the content is in the game already (game music)
- pressing the button is giving a feedback (mute on/off)

How does it work with no mouse?
- I did not pay attention to this requirement when I initially created it
- now the button has also mapped for the keyboard (M) and USB controller (Y on the one I'm using)

What confirms an action happened, or failed?
- music is muted and red X is above the icon
- I guess that failure would be that music plays while red X is on it or music is muted while no red X is visible
- I did not encounter a failure status so it is difficult to debug 

What happens at zero, at maximum, at longest string?
- I removed the text because I did not see it working at all intially
- Based on my quick tests after I built the project, the icon remains in the same location
- if the window's aspect ration breaks the defined viewport's width by being bigger, then the icon remains where the viewport is considered to be
=> this behavior places the icon above the "play view"
=> I don't consider it currently as a problem but I will pay attention to locked screen sizes to assure that scaling and aspect rations are respected accurately

Does it survive a save and load?
- No
- I did not program any save features, and I do not consider this project to be in a state that I should plan the design decision of saving the process
- For what it is worth, the music mute survives the scene change and restarting the game
=> more relevant for me currently, since it was part of my global variable learning goal

How does a new player learn it exists?
- via trial and error, yes

Element 3: Quest Log
------------------------------- 

What states can it be in?
- always present: the main object the player has in the scene
- boolean state: ok symbol appears if the player finished the quest

How does content get in, and out?
- each scene has a game manager which holds the name of its scene
- when the scene is loaded, the game manager informs its scene id to the game view scene
- the game view scene verifies that the provided scene has a quest
- if there is a quest, it and its status will be printed on the screen
- additionally, when a story/Warp ball can pass the collision information to the game manager if the ball is considered as the quest one

How does it work with no mouse?
- automated when the scene is changed
- no mouse needed to play the game

What confirms an action happened, or failed?
- the action happened when the new scene loads and text has updated
- the action also happened when the ok symbol appears above the quest name when the quest has been finished
- I don't remember if I wrote a safety net text to inform that something went wrong

What happens at zero, at maximum, at longest string?

- font size remains as what I defined as long as the window size is same or bigger than the defined viewport
=> font shrinks when the window size get smaller
- text's position has the same issues as with the Music Button icon

Does it survive a save and load?
- No
